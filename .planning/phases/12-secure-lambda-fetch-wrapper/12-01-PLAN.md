<threat_model>
## Trust Boundaries (Plan 12-01 scope)

| Boundary | Description |
|----------|-------------|
| build → runtime env (.env.local) | `NEXT_PUBLIC_API_BASE_URL` is bundled into the client. Treat as public, not a secret. |
| layout → Toaster portal | Sonner renders toasts via a React portal at the document root; any client component can call `toast.error(msg)` with arbitrary string content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-06a | Information disclosure | `toast.error(msg)` in `<Toaster />` | mitigate | Sanitization happens upstream in `client.ts` (Plan 12-02 `classifyError`) — by the time a string reaches `toast.error`, it has already been filtered. Plan 12-01 ships only the rendering surface; verification of sanitization is in Plan 12-02/12-04. |
| T-12-01a | Information disclosure | `<Toaster />` styling | accept | Sonner default styling does not capture/display raw response bodies — only the `message` string the caller passes. Risk is bounded by Plan 12-02's `message` field discipline. |
| (build-time) Tampering | Tampering | `.env.example` | accept | Documentation file only — has no runtime effect; the real risk is mis-configuration during onboarding (Phase 17), not this plan. |

ASVS Level 1: this plan introduces no new auth/authorization paths; the Toaster is a UI primitive with no privileged data access. No high-severity threats originate here.
</threat_model>
