# Phase 3 — UI Design Contract

> Visual and interaction contract for the layout chrome (Navbar / Sidebar / Footer / PageLayout / BrandMark). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase ships the chrome shell every screen phase plugs into. It does **not** ship screen content (Phases 6–10), the auth context (Phase 5), or any new design tokens (locked from Phase 2). The contract below references existing token utilities only — anything not covered by `frontend/web/styles/globals.css @theme` must be expressed as a Tailwind layout primitive (flex/grid/spacing scale) or as one of the two documented arbitrary-value escape hatches in §"Token Escape Hatches" below.

## Spacing Scale

Phase 3 consumes Tailwind's default spacing scale (4 px base unit) plus the two layout tokens shipped by Phase 2 (`w-rail` / `h-tab` = 64 px). No new tokens are added.

| Token | Value | Usage in Phase 3 |
|-------|-------|------------------|
| 1 | 4px | Inline gap between mobile tab-bar icon and label (reference `gap: 3` rounded to nearest scale step → use `gap-1`) |
| 1.5 | 6px | Mobile tab bar horizontal padding (`padding: '0 6px'` reference → `px-1.5`) |
| 2 | 8px | Tab-bar item internal padding (`padding: 6` reference rounded to scale → `p-2`); active sidebar indicator top/bottom inset (matches `top: 8 / bottom: 8` reference shared.jsx:70) |
| 3 | 12px | Sidebar avatar/brand row vertical breathing inside rail (visual gap between bottom avatar and rail floor) |
| 4 | 16px | Sidebar gap between brand block and items list (`marginTop: 18` reference rounded to nearest scale step) |
| 4.5 | 18px | Sidebar vertical padding inside rail (`padding: '18px 0'` reference shared.jsx:46 → `py-[1.125rem]` if exact; recommend `py-4` (16px) as the closest scale-step approximation — drift ≤ 2 px, acceptable per CONTEXT D-05 trade-off philosophy) |
| 6 | 24px | Footer block vertical padding; Navbar header vertical padding inside content (matches `padding: '24px 40px'` reference home.jsx:139) |
| 10 | 40px | Navbar header horizontal padding on desktop (`padding: '24px 40px'` reference home.jsx:139); footer horizontal padding on desktop |
| 5 | 20px | Mobile Navbar header horizontal padding (`padding: '18px 20px'` reference home.jsx:221) |
| **`w-rail`** | **64px** | Desktop rail width (Phase 2 token, `--spacing-rail`); content offset on `(app)` desktop wrapper as `pl-rail` |
| **`h-tab`** | **64px** | Mobile tab bar height (Phase 2 token, `--spacing-tab`); content offset on `(app)` mobile wrapper as `pb-tab` |
| 11 | 44px | Sidebar item button hit-target (`width: 44, height: 44` reference shared.jsx:60) — `w-11 h-11` |
| 13 | 52px | Mobile primary CTA circle (`width: 52, height: 52` reference shared.jsx:115) — `w-13` does not exist; use Tailwind arbitrary `w-[52px] h-[52px]` (size-only, non-tokenized — permitted) |
| 9 | 36px | Sidebar avatar circle (`width: 36, height: 36` reference shared.jsx:79) — `w-9 h-9` |

**Active sidebar indicator geometry** (shared.jsx:69–72):
- Position: `absolute`, `left: -10px` (negative offset outside rail inner padding), `top: 8px`, `bottom: 8px`, `width: 3px`
- Tailwind expression: `absolute -left-2.5 top-2 bottom-2 w-[3px] bg-accent rounded-sm`
- The `-left-2.5` (= `-10px`) and `w-[3px]` are layout primitives; `bg-accent` and `rounded-sm` are tokens.

**Exceptions:**
- `w-[52px] h-[52px]` for the mobile primary CTA — exact pixel value, no nearest scale step that matches the reference's 52 × 52 amber circle.
- `-left-2.5` (= `-10px`) for the active indicator — Tailwind's negative-margin scale step, matches reference exactly.
- `w-[3px]` for the active indicator bar — non-tokenized layout dimension, exact value matters visually.

## Typography

All font-family / font-size values come from existing Phase 2 tokens. Font-weights and line-heights are layout primitives (Tailwind core — `font-{weight}`, `leading-{ratio}`) and do not require new tokens.

| Role | Token / Class | Weight | Line Height | Usage |
|------|---------------|--------|-------------|-------|
| Brand wordmark | `font-display text-[18px]` (BrandMark default size 28 SVG + 18px wordmark — reference shared.jsx:22) | 800 (`font-extrabold`) | tight (`leading-tight` ≈ 1.25) | Brand mark "Recommend·a" wordmark, used inside Navbar (desktop) and AuthShell (Phase 4). Letter-spacing `-0.02em` → `tracking-tight`. The `[18px]` is a non-tokenized one-off (BrandMark internal sizing only); acceptable inside the BrandMark component file. |
| Navbar greeting | `font-body text-14` | 500 (`font-medium`) | 1.5 (`leading-normal`) | "Hi, {name}" string in logged-in Navbar variant (reference home.jsx:148–150 uses `fontSize: 13` — round up to nearest scale step `text-14`). Color `text-secondary`. |
| Navbar auth buttons | `font-body text-14` | 600 (`font-semibold`) | 1 (`leading-none`) | "Sign in" / "Create account" buttons (reference uses `.btn` class which Phase 4 owns; Phase 3 ships them as plain `<Link>` styled with text-14 + color tokens). |
| Sidebar tooltip / aria-label | n/a (visually hidden) | n/a | n/a | Desktop rail items are icon-only — no visible label. Each `<Link>` has `title={label}` and `aria-label={label}`. No tooltip component shipped this phase. |
| Mobile tab bar label | `font-body text-[10px]` | 500 (`font-medium`) | 1 (`leading-none`) | Reference shared.jsx:132 uses `fontSize: 10, fontWeight: 500`. The `[10px]` is below the smallest Phase 2 token (`text-12`) — use Tailwind arbitrary value, document as one-off. Color: `text-text-muted` (inactive) / `text-text-primary` (active). |
| Footer disclaimer | `font-body text-12` | 400 (`font-normal`) | 1.5 (`leading-normal`) | The literal disclaimer string (reference auth.jsx:31–32 uses `fontSize: 12`). Color: `text-text-muted`. |
| Footer link stubs | `font-body text-12` | 500 (`font-medium`) | 1.5 (`leading-normal`) | About / Privacy stub anchors. Color: `text-text-muted` (no hover token shipped — leave as-is). |

**Notes:**
- Body default for the entire app remains `font-body` size 16 / line-height 1.5 (already wired in `@layer base` in `globals.css`).
- Display family is reserved for the BrandMark wordmark in Phase 3. Screen phases (6–10) will use `font-display` for hero copy and section headings.
- Letter-spacing `tracking-tight` (= `-0.025em`) is the closest core utility to the reference's `-0.02em`; acceptable approximation.
- The two arbitrary font-size escapes (`text-[18px]` for the wordmark and `text-[10px]` for the mobile tab label) are intentional — both fall outside the Phase 2 type scale (12/14/16/20/28/40/64) and are tied to the reference's exact geometry. Document each occurrence with a `// non-tokenized: brand-mark wordmark size — see UI-SPEC §Typography` comment in the component file.

**Accent reserved for** (explicit list — never "all interactive elements"):
1. Active sidebar item indicator bar (3 px vertical bar at left edge of active rail item).
2. Mobile primary CTA fill (the central 52 × 52 circle in the bottom tab bar — the "Pick" Sparkles button).
3. Brand mark SVG gradient (the `<rect>` background of the BrandMark component, both gradient stops).
4. Brand mark wordmark middot character (`·` between "Recommend" and "a").
5. (Off-limits for Phase 3 chrome: Navbar buttons, Sidebar button hover state, Footer links, avatar circle. None of these use `bg-accent` or `text-accent`.)

**Active sidebar item color treatment** (matches reference shared.jsx:62–63):
- Inactive: `text-text-muted` icon, `bg-transparent`.
- Active: `text-text-primary` icon, `bg-surface-elevated` (panel approximation of the reference's `rgba(255,255,255,.05)` overlay) PLUS the 3 px vertical `bg-accent` indicator bar at left edge.
- Hover (inactive only): `text-text-primary` icon (CSS `:hover` pseudoclass + `transition-colors` — duration is a one-off Tailwind class `duration-150`; if duplicated 3+ times across screen phases, promote to a token).

**Token escape hatches (the only two arbitrary values permitted in Phase 3 chrome — see CONTEXT §Specifics):**
1. **Mobile primary CTA glow shadow** — `shadow-[0_6px_18px_rgba(245,181,68,0.35)]`. Reference shared.jsx:118. Phase 2 ships `--shadow-md`/`--shadow-lg`; this glow is a third one-off shape. Document inline in `Sidebar.tsx` with a comment: `// non-tokenized: amber glow on mobile Pick CTA — see UI-SPEC §Color Escape Hatches. Promote to --shadow-cta-glow if Phase 6 hero CTA reuses it.`
2. **Rail backdrop opacity approximation** — `bg-bg/70`. Reference shared.jsx:44 `rgba(8,8,9,.7)` — the rail uses a slightly darker shade than `--color-bg` (`#0a0a0b` ≈ rgb(10,10,11)). The Tailwind `bg-bg/70` opacity utility produces `rgba(10,10,11,0.7)` — drift of ~2 rgb units, undetectable on a dark UI. Document inline in `Sidebar.tsx`: `// approximation: --color-bg/70 stands in for reference rgba(8,8,9,.7) — promote to --color-rail-bg if reviewers spot drift at PR.`

**Backdrop blur (rail and tab bar) — token approximations:**
- Rail: reference `backdropFilter: blur(12px)` → use `backdrop-blur-md` (Tailwind v4 default = 12 px, exact match).
- Tab bar: reference `backdropFilter: blur(14px)` → use `backdrop-blur-lg` (Tailwind v4 default = 16 px, drift +2 px, acceptable).

## Responsive Behavior

Two-tier responsive — single breakpoint at Tailwind `md` (= 768 px). No icon-only intermediate tier (D-05).

| Breakpoint | Sidebar | Navbar (when rendered) | Footer | Content offset |
|------------|---------|------------------------|--------|----------------|
| `< 768px` (mobile, ~375 target) | Bottom tab bar visible (`flex md:hidden`); rail hidden | Mobile variant if rendered (small horizontal bar with BrandMark + bell) | In-flow at bottom of scroll content, above the fixed tab bar (no overlap — tab bar is fixed-position, footer scrolls above it within content area) | `pb-tab` (= 64 px) on the content column so content can scroll clear of the tab bar |
| `≥ 768px` (desktop, ~768 and 1440 targets) | Left rail visible (`hidden md:flex`); tab bar hidden | Home variant if rendered (full horizontal bar with BrandMark + auth/greeting) | In-flow at bottom of scroll content, full-width within the offset content column | `pl-rail` (= 64 px) on the content column to clear the fixed-position rail |

**Transition behavior at the 768 px boundary:** instantaneous swap (Tailwind responsive class toggle). No fade, no slide animation — matches the reference's plain `@media (min-width: 768px)` swap. Hot-reload at the breakpoint shows the rail appear and the tab bar disappear simultaneously. No `transition-opacity` or `transform` utilities applied to the rail/tab containers. (Animation tokens are deferred.)

**Z-index stack (Phase 3 only — modals and toasts are screen-phase concerns):**
- `z-0` (default): page content inside `<PageLayout>`'s children slot.
- `z-10`: `<Footer>` (above content gradients, below chrome).
- `z-20`: `<Navbar>` if rendered (above content, below sidebar when scroll behavior overlaps).
- `z-30`: `<Sidebar>` rail and tab bar (always above content; reference uses `zIndex: 5` — bumped to `z-30` here to leave headroom for screen phases that will introduce overlays at `z-40`+).

Tailwind core utilities `z-0`/`z-10`/`z-20`/`z-30` cover this — no custom z-index tokens.

## Interaction Contracts

| Surface | Interaction | Behavior |
|---------|-------------|----------|
| Sidebar item (rail and tab bar) | Click | `<Link>` navigates to `href`. No client-side state change required — Next.js handles route change; `usePathname()` re-runs and active state re-computes. |
| Sidebar item (rail) | Hover (inactive) | Icon color transitions from `text-text-muted` to `text-text-primary` over 150 ms (`transition-colors duration-150`). Background unchanged. |
| Sidebar item (rail) | Hover (active) | No-op — already at `text-text-primary` and `bg-surface-elevated`. |
| Sidebar item (rail) | Focus | Default browser focus ring acceptable for Phase 3 (no custom focus ring token shipped — `focus-visible:outline-2 focus-visible:outline-accent focus-visible:outline-offset-2` is the recommended Tailwind expression if executor wants explicit; otherwise relies on browser default + `outline-none` is forbidden). |
| Sidebar item (rail) | Disabled state | Not applicable Phase 3 — no items are conditionally disabled. (Phase 5 may add disabled visual on protected routes when logged out, but the current decision is to render them and let `RequireAuth` redirect — no chrome change.) |
| Mobile primary CTA (Pick button) | Click | `<Link href="/recommendation">`. No active state on the central CTA (it's always amber, regardless of pathname — the visual identity is fixed, matching reference). |
| Navbar bell | Click | `aria-label="Notifications (coming soon)"`, `disabled` HTML attribute set. No `onClick` handler. |
| Navbar `Sign in` / `Create account` buttons | Click | `<Link>` to `/login` and `/register` respectively. Phase 4 will register the actual route handlers. Phase 3 ships the links pointing at the future paths. |
| Avatar circle (rail bottom) | Click | `<Link href="/preferences">`. When logged-out, links to `/login` instead. |
| Footer About / Privacy stubs | Click | `<a href="#" aria-disabled="true" onClick={e => e.preventDefault()}>` — visually link-styled but no navigation. |
| BrandMark | Click | Brand mark inside Navbar wraps in `<Link href="/">`. BrandMark inside the rail does NOT wrap in a Link (reference shows it as static — clicking the rail brand position is unergonomic next to the Home item; defer to the explicit Home item). BrandMark inside AuthShell footer does NOT wrap in a Link. |

**Accessibility minimums (verified at Phase 3 PR):**
- Every icon-only `<Link>` / `<button>` has `aria-label` (or `title` + `aria-label`) per the Copywriting Contract table.
- Every focusable surface has a visible focus ring (browser default acceptable).
- Tab order on the rail follows the source order (Brand position → Home → History → Pick → Watch later → Preferences → Avatar).
- Tab order on the tab bar follows the source order (Home → Search-not-shipped-Phase-3 → Pick → Watch later → Profile/Preferences). **Phase 3 ships only 5 items in the tab bar matching the 5 sidebar routes** — the reference's "Search" slot is dropped (CONTEXT §Deferred — Search route is post-v1).
